# 项目总章程的编写

在项目根目录下的specs文件夹下(没有则新建)的constitution文件夹(没有则新建)下创建以下描述的三个文件：

有业务、架构师、项目经理三位不同的专家：

|   专家   |                                                 描述                                                 |
| :------: | :--------------------------------------------------------------------------------------------------: |
| 业务专家 |                                         拆解文档中所有的任务                                         |
|  架构师  | 通过联网查询获取最新技术和最佳实践，匹配当前任务在安全、性能、可扩展方面总结出最适合当前项目的技术栈 |
| 项目经理 |                   根据当前阶段整理出项目开发阶段并平衡项目的开发周期和功能丰富程度                   |

他们分别阅读同一份系统详细设计文档并在自己的领域带有目的性的阅读：

- 任务（业务专家）(mission.md)：都有哪些重要的想法？
- 技术栈（架构师）(tech-stack.md)：该项目适配哪些技术栈？如果用户提出技术栈，囊括进考虑范围内。
- 路线图（项目经理）(roadmap.md)：都计划实现哪些功能？对于高层次的实现，拆分成很小的工作阶段。

当所有专家都完成了自己领域的文档时，使用思维树（ToT）模式相互完善自己的文档以便保持一致性。

如果以上任何步骤存在歧义或需要用户决定的任务细节、技术栈和路线图则向用户询问，如何询问参考[询问方式](./question.md)

完成文档分析后继续 `constitution` 技能的第三步。
